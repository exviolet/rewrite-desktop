# 17 — Слэш-меню: вставка markdown-лесов и trigger phrases по `/`

**Статус:** active (2026-08-12)
**Репозиторий:** `web/` целиком. Rust, capabilities и схема БД не трогаются.

## Зачем

Аргумент **не** «в Obsidian так». Obsidian — редактор заметок, у него markdown это конечный
продукт; у нас markdown — леса вокруг промпта, который уезжает в терминал агента.

Настоящее основание: **`/` — единственный триггер без модификаторов.** Все 36 команд реестра
(`lib/shortcuts.ts`) сидят на `Ctrl`+что-то, часть с `Shift`/`Alt` сверху. У автора основная
клавиатура — 60% (Cidoo QK61 v2): нет F-ряда, стрелок и nav-кластера, `PgUp`/`PgDn` только
через Fn-слой. Меню на одной клавише — не «ещё один хоткей», а снятие хоткеев: `Ctrl+M`,
`Ctrl+Shift+M` и `Ctrl+K` получают путь без модификаторов.

Побочно закрывает и вторую боль: `Ctrl+K` (trigger phrases) — модальное окно на весь экран
ради вставки трёх строк.

## Решения автора (2026-08-12, сессия-грилл)

1. **GitHub Alerts выкинуты.** На исходных скриншотах их было 5 из 13 пунктов
   (`> [!WARNING]`, `> [!NOTE]` и т.д.). Это синтаксис рендеринга GitHub: в промпте
   Claude Code он не рендерится ничем, а «важно» дешевле сказать словом. Автор подтвердил:
   в Sendoff пишутся **только промпты**, доки — нет. Условие пересмотра: если README/issues
   начнут набираться здесь.
2. **Trigger phrases живут в том же меню, все и всегда в каретку.** Расхождение с `Ctrl+K`
   в режиме `phraseInsertMode: "prepend"` (дефолт — префиксом ко всему промпту) принято
   **сознательно**: `/` вызывается в конкретной точке текста, вставка в начало таба
   противоречила бы самому жесту. `Ctrl+K` свою настройку сохраняет — не трогать.
3. Связка move-tab / DnD (nav-клавиши без альтернативы + сломанный `reorderTab`) —
   **не в этот заход**, отдельной задачей.

## Каталог пунктов

Порядок секций: **Phrases → Formatting.** Фразы авторские — это ценный груз, markdown
генерика. Курсор **плоский сквозь секции** (конвенция сгруппированных пикеров, см.
`web/CLAUDE.md`).

| Секция | Пункт | Вставляет |
|---|---|---|
| Formatting | Code block | ` ``` ` … ` ``` `, каретка внутри |
| Formatting | Heading 1–4 | `# ` … `#### ` на строку |
| Formatting | Ordered List | `1. ` |
| Formatting | Task List | `- [ ] ` |
| Formatting | Unordered List | `- ` |
| Formatting | Horizontal Rule | `---` отдельной строкой |
| Phrases | (из `triggerPhrasesStore`) | `body` как есть, в каретку |

Набор Formatting — ровно тот, что был на скриншотах автора, минус алерты. Заголовки взяты
все четыре, хотя в промптах глубже третьего почти не встречаются: сузить набор автор не
просил, а молча урезать заказанное нельзя.

## Триггер и его отмена

`/` — обычный символ текста (`src/lib/`, `и/или`, `12/08`). Меню обязано открываться редко и
закрываться мгновенно, иначе получим шестой в этом проекте случай «интерфейс лезет, куда не
звали».

Правила (чистая функция `detectSlashQuery`):
- Открывается, только если `/` стоит **в начале строки или после пробела/таба**.
- Запрос — символы между `/` и кареткой. Пробел, перенос строки или `/` в запросе → `null`.
- Потолок длины запроса (24) — страховка от «меню живёт до конца абзаца».
- Ничего не нашлось по запросу → меню закрывается, а не висит пустым.

Детект идёт **по тексту перед кареткой, не по коду клавиши** — то есть работает на любой
раскладке по построению. Это важно: на ЙЦУКЕН физическая клавиша `Slash` даёт `.`, и проверка
по `e.code`/`e.key` открывала бы меню не от того символа.

## Клавиатура, пока меню открыто

| Клавиша | Действие |
|---|---|
| `↑` / `↓` | Движение курсора по плоскому списку |
| `Enter` / `Tab` | Вставить |
| `Escape` | Закрыть, текст не трогать |
| Любой ввод | Уточняет запрос либо закрывает меню (см. выше) |

Перехват обязан стоять **до** `useEditorKeymap`: иначе `Enter` уйдёт в `continueList`, а `Tab`
— в `indentSelection`.

## Два инварианта, которые легко снести

1. **Редактор не ре-рендерится на ввод.** `Editor.tsx` сознательно держит `renderContent === ""`,
   пока нет превью и подсветки (комментарий на `Editor.tsx:33`). Состояние меню в `Editor`
   допустимо только потому, что оно `null` в закрытом состоянии, а детект — одна регулярка по
   строке перед кареткой. **Не заводить подписку на контент ради меню.**
2. **Патч идёт мимо `onChange`.** Вставка использует существующий `applyPatch` (`setRangeText`
   + ручной `updateContent` + отмена висящего RAF). Свой путь записи не изобретать — висящий
   RAF откатит вставку.

## Позиционирование

Координат каретки в `<textarea>` нет — нужен зеркальный `div` с теми же шрифтом, padding'ом,
`leading`, `tracking` и режимом переноса. Техника в проекте уже обкатана: ровно так работает
backdrop подсветки поиска (`Editor.tsx:217-231`).

Отличие: зеркало для каретки строится из `getComputedStyle` самой textarea, а не из
Tailwind-классов. Причина — `tracking-wide` (letter-spacing) и `fontFamily` из настроек:
рукописная копия классов разошлась бы с реальностью на первой же смене шрифта, и меню уехало
бы от каретки на длинных строках.

Меню переворачивается вверх, если снизу не хватает места, и прижимается к правому краю
редактора, если вылезает.

## Чего НЕ делаем

- Не заводим настройку «выключить слэш-меню» — жильца нет, а `Escape` и пробел закрывают.
- Не тащим меню в `PickerModal`: примитив модальный, а это инлайн-попап у каретки.
- Не трогаем `phraseInsertMode` и `Ctrl+K`.
- Не добавляем `@`-триггер для путей/файлов — ветка «image→path» в ROADMAP не расковыряна.
- Не добавляем таблицы, ссылки, footnotes: их не было в запросе, у промптов на них спроса нет.
