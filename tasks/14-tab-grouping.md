# Task 14 — Tab grouping (группы табов внутри workspace)

**Status:** **done** — все три фазы (web merge `1554653`), 2026-07-27
**Issue:** [#4](https://github.com/exviolet/rewrite-desktop/issues/4)
**Owner:** Claude Opus (спек) → исполнитель по договорённости

## Почему сейчас

Issue #4 был запаркован с явным условием реанимации:

> **Revive if:** after living with workspace isolation daily, there is a concrete need
> to organize many tabs *within* one workspace.

**Условие выполнено** (подтверждено автором 2026-07-27): после 2+ недель жизни с
workspaces боль осталась **внутри одного workspace**. Второй пользователь (друг) просит
группы давно и настойчиво — тот же канал, что дал фичу поддержки шрифтов.

Важно помнить разрез из issue: workspaces **прячут** чужие табы и убирают шум; группы
**ничего не прячут** (кроме свёрнутых) и шум не уменьшают — они добавляют структуру
внутри одного вида. Это дополняющие механизмы, не конкурирующие.

## Scope v1

**Входит:**
- Именованная цветная группа: `name`, `color`, `collapsed`.
- Табы группы идут **непрерывным run'ом** в полосе, под общим заголовком-чипом.
- Свернуть/развернуть группу в один клик (свёрнутая = табы скрыты, виден только чип).
- Создать группу / переименовать / сменить цвет / расформировать (ungroup).
- Добавить таб в группу и убрать из неё (контекст-меню + DnD).
- Закрыть все табы группы.
- Персист: группы переживают рестарт, едут в бэкапе.

**НЕ входит в v1** (не расширять без отдельного решения):
- Вложенные группы, группы поверх workspace'ов, шаринг групп между workspace'ами.
- Автогруппировка (по домену/проекту/времени), сохранённые сессии групп.
- Показ группы в `GlobalSearch` (там строка и так плотная; в `TabSwitcher` — входит, см. ниже).
- Drag группы целиком (перетаскивание всего run'а). Сначала DnD одного таба.

## Модель данных

```ts
interface TabGroup {
  id: string;              // uuid
  name: string;
  color: TabGroupColor;    // фиксированная палитра, НЕ произвольный hex
  collapsed: boolean;
  workspaceId: string;     // группа живёт внутри workspace (см. ловушку про перенос)
  createdAt: number;
}

type TabGroupColor = "accent" | "green" | "yellow" | "red" | "purple" | "gray";

interface Tab {
  // ...существующее
  groupId?: string;        // аддитивно, как workspaceId
}
```

**Палитра, а не hex:** цвета должны читаться в светлой и тёмной теме и не спорить с
accent-подсветкой активного таба. Произвольный цвет из color picker'а даст нечитаемые
комбинации и потребует расчёта контраста — это не v1.

**Персист:** новый object store `tabGroups` → **DB v5 → v6, аддитивно** (ровно как
`workspaces` в v4→v5). Миграций нет: у старых табов `groupId === undefined` = «без
группы», это валидное состояние. Данные друга не задеваются — изменение **не
разрушающее**, координация не требуется, но предупредить стоит.

**Бэкап обязан возить `tabGroups`** — иначе восстановление из бэкапа схлопнет всю
группировку. Ровно на этом уже спотыкались с workspaces; повторить ошибку нельзя.

## Решения (приняты, с обоснованием)

### 1. Pin и группа — взаимоисключимы
Закрепление таба **убирает его из группы**; добавление закреплённого таба в группу
**снимает пин**. UI показывает это явно (в контекст-меню пункт неактивен с подсказкой).

Причина не косметическая: `partitionPinned` глобально пересортировывает массив (pinned
влево) после **каждого** reorder. Закреплённый член группы был бы вырван из своего run'а,
и непрерывность группы развалилась бы при первом же перетаскивании. Так же решает Chrome.

### 2. Непрерывность run'а — инвариант, а не соглашение
Ввести в `lib/tabUtils.ts` чистую функцию `partitionGroups(tabs)` по образцу
`partitionPinned`: стабильно стягивает табы одной группы в непрерывный run, порядок
групп определяется позицией их **первого** таба, порядок внутри группы сохраняется.

Применять **после** `partitionPinned` в тех же местах, где он сейчас вызывается
(`reorderTab`, `togglePin`, создание таба). Иначе группа разъедется, а вернуть её
руками пользователь не сможет.

### 3. Сворачивание не трогает данные и не закрывает табы
`collapsed: true` — **только видимость в полосе**. Табы живы, ищутся через `Ctrl+T` и
`Ctrl+Shift+D`, персистятся.

Если активный таб оказался внутри сворачиваемой группы — активация переезжает на
ближайший видимый таб (сначала справа от run'а, иначе слева). Если видимых табов не
остаётся вовсе (всё в свёрнутых группах) — **активация остаётся на скрытом табе**, а чип
группы подсвечивается как активный. Не создавать новый таб и не запрещать сворачивание:
и то и другое хуже (мусорный таб / необъяснимый запрет).

### 4. Расформирование ≠ закрытие
Ungroup убирает `groupId` у табов и удаляет запись группы; **табы остаются**. Закрытие
группы (со всеми табами) — отдельный пункт меню, и он проходит через существующий
`pendingClose`-путь, если внутри есть несохранённые табы.

### 5. Группы скоуплены workspace'ом
`moveTabToWorkspace` **обязан очищать `groupId`** (или, если в целевом workspace есть
группа с тем же именем — это v2, не сейчас: просто очищать). Иначе таб уедет в чужой
workspace, продолжая ссылаться на группу, которой там нет.

Осиротевшие группы (все табы ушли/закрыты) удалять сразу — пустой чип в полосе бесполезен.

## Ловушки (из чтения кода 2026-07-27)

- **`tabsMetaEqual` в `TabBar.tsx` обязан получить `groupId`.** Без этого полоса
  «замерзает» при переносе таба в группу — тот же класс бага, что уже случался **дважды**
  (`orcaBinding`, `workspaceId`). Сами поля группы (`name`/`color`/`collapsed`) живут в
  другом сторе, значит TabBar подписывается на него отдельно — учесть в перерисовке.
- **`reorderTab` работает по id** (индексы отфильтрованного списка не совпадают с
  глобальными). Не откатывать на индексы. Drop на таб внутри группы должен **и** двигать
  таб, **и** присваивать ему `groupId` цели — иначе он визуально сядет в run, а логически
  останется вне группы.
- **`closeTabsToRight` считает «правее» по видимому списку.** Со свёрнутыми группами
  «видимый» перестаёт совпадать с «существующим»: решить явно — закрывать скрытые табы
  свёрнутой группы, попавшие в диапазон, или нет. **Рекомендация: закрывать** (пункт
  говорит «правее», а не «правее из видимых»), но показать в подтверждении реальное число.
- **`closeSavedTabs` / `closeOtherTabs` скоуплены workspace'ом** — при добавлении
  «закрыть группу» не сломать этот скоуп и не начать ходить по глобальному массиву.
- **`canCleanupTab`** авто-чистит пустые табы. Пустой таб внутри группы тоже подпадёт —
  проверить, что авто-очистка не оставляет пустую группу-призрак (см. решение 5).
- **DnD уже существует** для reorder — новая логика должна лечь в него, а не заводить
  второй механизм перетаскивания.

## Дополнения после живой обкатки v1 (2026-07-27, web merge `e93bd43`)

Автор погонял v1 вживую и заказал три вещи. Первая была **явно вне v1** по спеку — решение
пересмотрено им же после реального использования, это нормальный порядок (сначала пощупать).

1. **Перетаскивание группы целиком.** Чип — ручка, run уезжает к позиции цели и не
   рассыпается. Реализовано переносом **первого** члена: `arrangeTabs` подтянет остальных,
   поэтому отдельной логики для хвоста нет. Дроп группы на другую группу ставит run рядом,
   **не сливает** их. Перетаскивание группы держится в отдельном ref — спутать «таб внутрь
   группы» с «группа к позиции» нельзя, у них разные обработчики.
2. **Множественный выбор (`Ctrl`+клик)** → положить пачку в группу или перенести в другой
   workspace. Ключевое: Ctrl+клик **не переключает активный таб** (иначе редактор уезжал бы
   посреди набора пачки). Выделение эфемерно (в `saveSession` не попадает), скоуплено активным
   workspace и чистится от id закрытых табов. **Пачка применяется, только если жест начат с
   выделенного таба** — ПКМ/`Ctrl+G` по невыделенному остаётся одиночным действием, иначе меню
   молча трогало бы не то, на что нажали. Подписи показывают число.
3. **`Ctrl+T`: цвет группы полосой слева** — читается периферийным зрением при проматывании,
   в отличие от метки в конце плотной строки. Точка у метки убрана как дубль цвета.

Заодно исправлено: **цвет новой группы — первый НЕзанятый**, а не по счётчику. По счётчику
новая группа легко получала цвет уже существующей, и в полосе две разные группы выглядели
одинаково (поймано вживую: `Пачка` получила жёлтый при живых жёлтых `Заметках`).

Проверено вживую: Ctrl+клик набирает выделение не трогая активный таб; `Ctrl+G` показывает
«Положить 3 таба…» и кладёт всю пачку; run переезжает целиком и встаёт **после закреплённых**
(пины держат начало полосы — верно); дроп группы на группу не сливает их; в `Ctrl+T` 8 строк
с цветной полосой и 4 без. `tsc -b` + `lint` + прод-сборка = 0.

## Решения по открытым вопросам (закрыты автором 2026-07-27)

### 6. Хоткей — `Ctrl+G`, через пикер групп
`Ctrl+G` открывает **модалку-пикер групп активного workspace** со строкой создания
(«+ Новая группа»), ровно как `WorkspaceSwitcher`. Выбор строки — положить активный таб в
эту группу; строка создания — создать группу и положить в неё.

Почему пикер, а не «создать группу молча»: это **седьмой консьюмер примитива из #9**, то
есть стоит ~40 строк, даёт поиск по имени и `↑↓` бесплатно, и не требует изобретать
второй жест для «в какую именно группу».

`Ctrl+G` **свободен** (проверено по `useKeyboardShortcuts.ts` — `KeyG` не занят нигде).
Сворачивание/разворачивание в v1 остаётся на клике по чипу: пока не видно, что этот жест
повторяется чаще, чем «положить таб в группу». Если после обкатки заболит — `Ctrl+Shift+G`
зарезервирован под toggle.

> **Временность зафиксирована.** Автор вспомнил про обсуждавшуюся кастомизацию хоткеев —
> запись есть: ROADMAP, сессия 2026-07-07, «**Кастомизация hotkeys — кандидат.** Уточнено:
> именно keyboard shortcuts (remap действие→клавиша, персист, UI редактирования). Хорошо
> очерчено, помогает и другу. Спек — когда станет active». То есть фича не забыта и не
> отклонена — она в статусе кандидата без спека. Когда дойдёт, дефолт `Ctrl+G` перестанет
> быть безальтернативным, и это ещё один довод не плодить сейчас второй хоткей под toggle.

### 7. Группа показывается в `TabSwitcher` (`Ctrl+T`) — входит в v1
Цветная метка группы у строки, рядом с меткой tmux-привязки. Строка уже плотная, поэтому:
метка **только цвет + имя, без иконки**, и она **не участвует в fuzzy-скоринге** в v1
(иначе `bestMatch` придётся расширять пятым источником — это отдельное решение).

### 8. `closeTabsToRight` со свёрнутыми группами — закрывать, показывать число
Принята рекомендация: пункт говорит «правее», а не «правее из видимых», поэтому скрытые
табы свёрнутых групп, попавшие в диапазон, **закрываются**. Но подтверждение обязано
показать **реальное** число закрываемых табов — иначе пользователь потеряет то, чего не
видел на экране.
